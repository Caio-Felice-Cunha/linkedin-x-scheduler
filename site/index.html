Architecture

One manifest, one orchestrator, replaceable platform adapters.

batch.json→validate + packets→orchestrator→LinkedIn / X adapter→queue verification→state + evidence

Manifest

Content, media, target platform, wall-clock schedule, timezone, and account guard form one versionable input.

Validator

Rejects missing text/assets, incompatible media counts, duplicate IDs, and unsupported platform/template combinations before a composer opens.

Orchestrator

Orders work, injects adapters, resumes verified posts, stops on safety failures, and owns the final run report.

Adapters

Contain volatile selectors and native-UI details. Core batching and state logic stay independent of either platform.

Workflow and state

Every item advances through observable, resumable states.

  1. 01validated

    Schema, assets, account, and schedule checked.

  2. 02composed

    Text and media placed in the native composer.

  3. 03scheduled

    Native schedule controls receive the wall-clock value.

  4. 04verified

    The scheduled queue is reconciled as source of truth.

  5. 05reported

    State, screenshots, and outcome remain available for resume.

Duplicate guard

Verified state and live-queue reconciliation prevent a retry from silently scheduling the same item twice.

Live-publish guard

If an adapter detects immediate publication, the entire batch aborts and raises an operator alert.

Bounded retries

Selector or verification failures stop with precise state; the orchestrator does not loop blindly.

Execution boundaries

Same batch contract. Three deliberately different capabilities.

Demo mode
Local fixture + mock adapter + static report. No Playwright import, CDP, social URL, or external write.

Dry-run mode
Attaches to Chrome and rehearses the native flow, but stubs the terminal schedule click.

Live mode
Requires explicit --live, uses native schedule UI, then verifies each queue.

Quality and limits

Automation is treated as an operator tool, not an unattended promise.

0demo external writes
5observable steps per item
2independent live adapters
1durable state contract
  • Unit tests cover manifests, order, state, report determinism, resume, adapter injection, and safety stops.
  • Pages tests cover desktop/mobile rendering, keyboard navigation, report parity, no external requests, and no console errors.
  • Live adapters depend on platform DOM and can require selector maintenance after UI changes.
  • Native scheduling uses the browser's wall-clock timezone; operators must verify platform queues.
